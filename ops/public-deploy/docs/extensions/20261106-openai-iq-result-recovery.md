## 用户结果与管理员诊断

`GET /api/v1/openai-iq` 只返回明确列出的展示字段。查询先限定当前用户可访问的活跃 OpenAI 分组，再按模型与分组独立选择最近的有效结果。有效结果必须为 `correct` 或 `incorrect` 且有检测时间，按 `checked_at DESC, id DESC` 确定同时间记录。更新的 `error`、`skipped` 和 `pending` 不覆盖此前的有效结果，也不会刷新它的时间。不同模型之间不回退借用结果。

每张有效结果保留原测试题目、标准答案、模型回答、完整文本输出和真实检测时间。历史模型与分组组合没有有效结果时显示中性「暂无结果」；当前配置选中的可见分组即使从未测试也有中性占位。已无权访问的分组不进入结果或汇总。用户响应不含内部错误、返回模型别名、请求编号、上游账号和预算预留；加载失败返回通用提示。

管理员使用独立鉴权接口 `GET /api/v1/admin/openai-iq/diagnostics?page=1&page_size=20` 查看历史，单页最多 50 轮。普通用户不能访问。历史包括所有轮次状态、原题目与结果、错误说明，以及存在时的预留、实际支出和用量关联信息。后台设置页单独加载该区块，诊断读取失败不阻止配置编辑。全部历史和预算记录继续保留。

独立审核后的修补：中性「暂无结果」卡不显示检测时间。管理员诊断严格解析整数分页参数，页码上限为 1,000,000；格式错误、超出整数范围或页码超过上限时返回 HTTP 400，不执行历史查询。仓储也校验有效范围，最大偏移在 32 位整数范围内，避免极大页码乘法溢出。默认分页和单页最多 50 条的行为保留。

## 未确认费用与终止原因

`IQBudget` 在既有实际支出、预留和剩余预算之外，为管理员提供 `unconfirmed_usd` 与 `unconfirmed_since`。活跃租约下的 pending 请求可能仍在执行，其预留属于在途额度；结果已终止、轮次已终止或租约已过期但未匹配到可信用量的预留属于未确认费用。宽限时间来自持久化的完成或过期时间，不因重复读取、下一轮或重启重新计时。

协调器为迟到用量保留 5 秒宽限。若未确认费用造成额度不足，而且全部在途预留即使结算为零也无法释放足够额度，宽限结束后将剩余分组标为 skipped，并在管理员诊断说明「费用未确认占用预算」。此前遗留的未确认费用不再引发重复的整轮空等。在途请求仍可能释放足够额度时继续等待；正常迟到用量到达后，准入恢复并保留每次请求的完整额度预留与单次上游尝试限制。

宽限仅结束排队，不会释放或清零未知费用。已有严格用量匹配与实际成本结算保持不变，错误请求编号、Key、用户、分组、UA、无效或重复用量不能误结算。检测关闭后、下一轮与重启后仍继续核对迟到用量。

未发起的请求分别记录关闭、分组移除、执行取消、时间准入截止、预算准入失败和未确认费用占用的原因。剩余时间少于 HTTP 120 秒加写入余量 5 秒时停止新请求；9 分钟轮次时间上限与 10 分钟数据库租约分别处理。兜底最终化明确标为未能记录具体原因，不再混称关闭或超时。已开始请求的结果写入全部结束后才完成轮次。
